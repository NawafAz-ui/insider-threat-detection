SPEDIA Data Preparation

This report shows the dataset the prototype uses, SPEDIA: where it came from, how it was checked, put into the prototype's file layout, preprocessed and split into a training and a test part, and the result of the first prototype run on it. CERT r4.2 stays the original dataset of the research and is planned for Capstone B.

Prepared on 15 November 2026 and updated on 16 November 2026 for the two-part split and the first run. Numbers are copied from the run's own records in backend/data/spedia on this laptop.

1. Summary

  • SPEDIA version 2 from Zenodo (DOI 10.5281/zenodo.15525713), licence CC BY 4.0, one file of 45.7 MB. Its checksum matches the published one.
  • 72,250 events from 06 to 30 March 2025. 55,649 fit the five files of the prototype's layout, and 16,601 have no place in it (10,114 shell commands, 5,399 login records and 1,088 events without a user).
  • All files passed the input check and gave 246 sessions of 10 users, 110 of them malicious.
  • Split by time into two parts only: 196 training sessions (78 malicious) and 50 test sessions (32 malicious). There is no validation part.
  • The prototype now runs on SPEDIA. On the test part the combined score reached precision 0.94, recall 0.94 and F1 0.94.

2. Why this dataset

CERT r4.2 is the original dataset of the research, but it is 16 GB unpacked, too large for a prototype, and it was removed from this laptop. No small public dataset in the exact CERT layout with labelled insiders was found: the only small CERT release (r1, 88 MB) has no answer key. SPEDIA is the second dataset already named in the Research and Methodology report (reference D2). It is small, labelled and openly licensed, and the prototype has a converter for it (itd/spedia.py).

4. Conversion to the prototype's layout

The converter reads a checked mapping (backend/spedia_mapping.json) that names the SPEDIA columns and event types for each CERT file. The result is in backend/data/spedia_cert, where the dashboard's run panel lists it.

CERT fileTaken from SPEDIARows

logon.csvBuilt from the activity: a session starts at a user's first event on a host and ends at the last event before a break of 30 minutes492
answers.csvEvents marked Anomaly = 129,515

Left out: 10,114 shell commands (9,250 of them marked as anomalies, so much of the real participants' attack activity), 5,399 login records and 1,088 events without a user name. SPEDIA's own login records come from the Linux login log of the exercise servers. Used as sessions, 2,336 of 3,031 sessions held none of the kept events, 1,316 records were the same login written twice in one second, and 21% of the events (11,914 of 56,737) fell outside every session. Sessions built from activity keep 99% of the events and leave no session empty. Checking the real file showed four faults in the converter, which were fixed and tested: Disconnect events were counted as connections, "Login" also matched "Login Failed", file names stored in Path were ignored, and events without a user were put under one shared user called "unknown".

6. Training and test split

The sessions are in time order and are cut at 80%. There is no validation part: the flag thresholds, the calibration and the model weights come from five-fold cross-validation inside the training part, and the test part is used once, for the result.

7. First prototype run on SPEDIA

On 16 November 2026 the main database was backed up (backend/backups/2026-11-16_1707) and the engine trained and scored the prototype on SPEDIA: 246 sessions, 111 flagged, flag threshold 35.5. The run was repeated the same day after the fix that lets a session join its user's normal behavior only after it has ended, because 40 of the 246 SPEDIA sessions overlap another session of the same user. 10. Limits

  • The dataset is small (10 users, 246 sessions) and nearly half malicious, so its results cannot be compared with CERT results.
  • Shell commands, where much of the real participants' attack activity is, are not used, because the CERT layout has no file for them.
  • The dashboard screenshots and docs/DEMO.md still show the earlier generated data.
